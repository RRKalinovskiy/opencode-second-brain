# Второй мозг workspace

Файловая база знаний в `brain/`. Цель — не перечитывать проект каждый раз и не раздувать контекст.

## Когда использовать
- Задача занимает больше одного шага: анализ, поиск, проверки, правки > 1 файла.
- Нужно понять, что уже известно по проекту, модулю или задаче.
- Нужно сохранить итоги сессии, решение или handoff.
- Нужно проверить, нет ли уже ответа в документации, коде или прошлых сессиях.

Не использовать для тривиальных правок в один файл, если ответ уже виден в коде.

## Быстрый старт
```bash
py -3 brain/brain.py pack "задача"   # контекст под задачу, ≤ 7000 символов
py -3 brain/brain.py brief           # STATE + последняя сессия + карта
py -3 brain/brain.py search "термин" # BM25 + префиксы + синонимы
py -3 brain/brain.py lint            # ссылки, размеры, frontmatter
py -3 brain/brain.py stats           # размеры файлов
```

## Карта
| Файл | Когда читать |
|---|---|
| `brain/STATE.md` | Текущий фокус, открытые вопросы, следующие шаги. |
| `brain/PROJECT.md` | Каталоги, репозитории, окружение, команды. |
| `brain/areas/*.md` | По одной области знаний на файл: структура, факты, риски. |
| `brain/GLOSSARY.md` | Термины проекта. |
| `brain/DECISIONS.md` | Принятые решения. |
| `brain/sessions/` | Ручной журнал по датам. |
| `brain/sessions/auto/` | Автожурнал плагина: черновик, требует проверки. |
| `brain/playbooks/work.md` | Протокол работы с вторым мозгом. |
| `brain/templates/` | Шаблоны сессии, области и решения. |

## Чтение
1. Запустить `pack` с формулировкой задачи.
2. Открыть только файлы/секции из выдачи.
3. Если факта нет — `search`, затем `read` с `offset`/`limit` или `grep`.
4. Не читать `brain/` целиком и не сканировать весь репозиторий.
5. Большие документы читать только нужными разделами, а не целиком.
6. `sessions/auto/` можно использовать как след прошлых ходов, но проверять по коду и ручному журналу.

## Запись
В конце задачи:
1. Просмотреть `brain/sessions/auto/YYYY-MM-DD.md`; это черновик, а не итог.
2. Дописать `brain/sessions/YYYY-MM-DD.md` (задача, сделано, найдено, решения, следующие шаги).
3. Обновить `brain/STATE.md` (фокус, вопросы, следующие шаги).
4. Устойчивый факт — в `brain/areas/*.md`; решение — в `brain/DECISIONS.md`.
5. Запустить `py -3 brain/brain.py lint`.

## Автожурнал
- Плагин: `.opencode/plugins/second-brain`; срабатывает на `session.execution.succeeded` и `session.idle`.
- Пишет последний запрос и последний текст ассистента в `sessions/auto/YYYY-MM-DD.md`; LLM не вызывает.
- Секреты редактируются по типовым шаблонам, текст обрезается; tool calls и детали не сохраняются.
- Работает только в проекте с `brain/brain.py`. Если файла нет — плагин молчит.

## Правила
- Один факт — одно место; не дублировать документацию.
- Ссылка + вывод + дата, а не копия.
- Секреты и персональные данные не писать.
- Непроверенное помечать «не подтверждено».
- Сессия — до ~80 строк, область — до ~300 строк.

## Definition of done
- Контекст собран через `pack`/`search`, а не сканированием репозитория.
- Автожурнал просмотрен, выводы перенесены в ручной журнал.
- Принятые решения и новые факты записаны.
- `lint` не показывает ошибок.
- В ответе — только вывод, изменённые файлы и следующий шаг.
